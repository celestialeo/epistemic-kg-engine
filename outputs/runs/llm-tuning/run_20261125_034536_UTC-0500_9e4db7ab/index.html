The input document

1. A foundation LLM, also called a base LLM or a pre-trained LLM, is a general-purpose large language model. A foundation LLM is trained on enough natural language to learn a great deal about grammar, words and idioms. A foundation LLM can generate helpful sentences about the topics it was trained on and can perform creative tasks such as writing poetry. However, a foundation LLM is not a complete solution for machine learning tasks such as classification or regression. For classification and regression tasks, a foundation LLM serves as a platform rather than a complete solution. Fine-tuning turns a foundation LLM into a solution for a specific application. Distillation is a secondary process that creates a smaller version of a fine-tuned LLM with fewer parameters.

2. Foundation LLMs recognize patterns so well that foundation LLMs often need only a modest amount of additional training to perform a specific task. This additional training is called fine-tuning. Fine-tuning trains a foundation LLM on examples that are specific to the task of the application. Engineers can often fine-tune a foundation LLM with only a few hundred to a few thousand training examples. Standard fine-tuning is computationally expensive, because standard fine-tuning updates the weights and biases of every parameter on each backpropagation iteration. Parameter-efficient tuning is a less expensive alternative to standard fine-tuning, because parameter-efficient tuning updates only a subset of the parameters on each backpropagation iteration. A fine-tuned LLM usually makes better predictions on its task than the foundation LLM does. A fine-tuned LLM has the same number of parameters as the foundation LLM it came from. For example, fine-tuning a foundation LLM that has ten billion parameters produces a fine-tuned LLM that also has ten billion parameters.

3. Fine-tuned LLMs usually have a very large number of parameters. As a result, generating predictions with a fine-tuned LLM requires large computational and environmental resources. Many of those parameters are typically irrelevant to a specific application. Distillation creates a smaller LLM from a larger LLM. The distilled LLM generates predictions faster and requires fewer computational and environmental resources than the larger LLM. However, the predictions of the distilled LLM are generally somewhat worse than the predictions of the larger LLM. LLMs with more parameters almost always make better predictions than LLMs with fewer parameters.

4. The most common form of distillation uses bulk inference to label data. In this form of distillation, the larger LLM acts as a teacher model and the smaller LLM acts as a student model. The teacher model labels a dataset, and the labeled dataset is used to train the student model. Through the labels, the teacher model passes its knowledge to the student model. For example, to moderate comments in real time, a team could run a large toxicity-scoring model offline to label training data, and then use the labeled data to distill a student model small enough to score live comments. A teacher model can sometimes produce more labeled data than the teacher model itself was trained on. A teacher model can also give the student model a numerical score instead of a binary label. A numerical score gives the student model a richer training signal than a binary label does. The richer training signal helps the student model predict borderline cases as well as clearly positive cases and clearly negative cases.

5. Prompt engineering lets the end users of an LLM customize the output of the LLM by stating in the prompt how the LLM should respond. Like people, LLMs learn well from examples. One-shot prompting supplies one example in the prompt. For example, a one-shot prompt can show that a peach belongs to the drupe fruit family and then ask for the fruit family of an apple, and the LLM can answer that an apple is a pome. Few-shot prompting supplies multiple examples in the prompt. For example, a few-shot prompt can show that a plum is a drupe and that a pear is a pome, and then ask for the fruit family of a lemon. In few-shot prompting, the examples in the prompt act like training examples. Zero-shot prompting supplies no examples in the prompt. Zero-shot prompting sometimes works, but LLMs benefit from context. For example, a zero-shot prompt that mentions only the word apple might return information about the technology company Apple instead of the fruit. Prompt engineering does not add, remove or change the parameters of an LLM. Instead, prompt engineering relies on the existing pattern-recognition ability of the LLM.

6. Online inference generates predictions at the time a request is served. Some LLMs are too large for online inference to be practical for tasks such as regression or classification. For this reason, many engineering teams use offline inference instead of online inference. Offline inference, also called bulk inference or static inference, means that an LLM generates predictions in advance and caches the predictions, rather than generating predictions at serving time. Offline inference saves computing resources and makes it possible to use larger LLMs. Slow prediction is acceptable for a task that runs only weekly or monthly. For example, Google Search used an LLM in offline inference to cache a list of more than 800 synonyms for Covid vaccines in more than 50 languages. Google Search then used the cached list to identify queries about vaccines in live traffic. LLMs generally inherit biases from the data used to train the LLM and from the data used to distill the LLM. For this reason, LLMs should be used fairly and responsibly.
