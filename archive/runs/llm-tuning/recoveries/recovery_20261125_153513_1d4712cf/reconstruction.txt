A foundation llm is trained on natural language and learns about grammar, words, and idioms. It can perform creative tasks such as writing poetry and generate helpful sentences about topics. However, it does not serve as a complete solution for machine learning tasks such as classification or regression; instead, it acts as a platform for these tasks. Fine tuning transforms the foundation llm into a solution for a specific application, while distillation creates a smaller version of a fine tuned llm with fewer parameters and is a secondary process that performs these transformations.

Foundation LLMs recognize patterns so well that they often need only a modest amount of additional training. This additional training is called fine tuning, where engineers can often fine tune a foundation LLM with only a few hundred to a few thousand training examples on examples that are specific to the task of the application. Standard fine tuning updates the weights and biases of every parameter on each backpropagation iteration because it is computationally expensive; however, parameter efficient tuning is a less expensive alternative to standard fine tuning as it updates only a subset of the parameters on each backpropagation iteration. Fine tuning a foundation LLM that has ten billion parameters transforms into a fine tuned LLM that also has ten billion parameters. Usually, a fine tuned LLM makes better predictions on task than the foundation LLM it came from, and a fine tuned LLM has the same parameter count as the foundation LLM.

Fine tuned llms usually have very large number of parameters. Generating predictions with a fine tuned llm need large computational and environmental resources. Parameters are typically irrelevant to specific application of many. Distillation creates smaller llm from a larger LLM. Distilled llm generates predictions faster than larger llm for predictions. Predictions of the distilled llm is generally somewhat worse than predictions of the larger llm. LLMs with more parameters almost always makes better predictions on task than better predictions than LLMs with fewer parameters.

In distillation processes, bulk inference applies labels to data. In this form of distillation, a larger llm acts as the teacher model role and a smaller llm acts as the student model role. The teacher model labels a dataset. A team could run a large toxicity scoring model offline to label training data, which creates labeled data that can sometimes contain more information than the teacher model itself was trained on. Alternatively, the teacher model could use the labeled data to distill a student model small enough to score live comments. Through labels, the teacher model passes knowledge to the distilled llm and gives numerical scores to the student model. A richer training signal enables the distilled llm to predict borderline cases, predict clearly positive cases, and predict clearly negative cases.

Prompt engineering enables end users of an llm to customize the output of the LLM by stating in the prompt how the LLM should respond. It relies on existing pattern recognition ability of the LLM and does not add, change, or act on parameters of an LLM. Examples in the prompt acts_as training examples. Zero shot prompting supplies examples in the prompt with none, but might give information about the technology company apple instead of the fruit when the zero shot prompt that mentions only the word apple is used. An llm benefits from context. Few shot prompting gives multiple examples in the prompt and can show that a plum is a drupe or that a pear is a pome, while asking for the fruit family of a lemon. One shot prompting gives one example in the prompt and can show that a peach belongs to the drupe fruit family or ask for the fruit family of an apple.

Online inference creates predictions at the time a request is served. However, llms are too large for online inference for tasks such as regression or classification. Consequently, engineering teams use offline inference instead of online inference. Offline inference is also called bulk inference and does not involve online inference; it saves computing resources and reduces consumption of computing resources while enabling use of larger llms. Slow prediction is acceptable for a task that runs only weekly or monthly. In practice, google search used an llm in offline inference to cache a list of more than 800 synonyms for Covid vaccines in more than 50 languages and to identify queries about vaccines using a cached list. Generally, llms learn from biases from the data used to train or distill the LLM. Therefore, llms should be used fairly according to fair use and should be used responsibly according to responsible use.
